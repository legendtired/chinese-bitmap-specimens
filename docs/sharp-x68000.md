# Sharp X68000：原生 16×16 JIS 字模导出

本工具从指定版本的 X68000 CGROM 导出 **6,877 个 JIS 映射字形**，其中 6,876 个非空字形、6,353 个汉字，另含空白的全角空格 U+3000。保留原生 16×16 点阵，不放大、不裁切，不用其他字体补字。公开仓库仅包含脚本、说明及不含 ROM 数据的测试；完整 ROM 与完整 BDF 不随仓库分发。

## 输入与来源

输入为自行准备的 `cgrom.dat`，必须同时符合以下大小与校验值：

- 大小：786,432 字节（768 KiB）。
- SHA-256：`c4e47e1480af0b00b330a49650480c8caa34054a6e97db7ae03cbade9890185d`。
- 对照识别信息：CRC32 `9f3195f1`，SHA-1 `8d72c5b4d63bb14c5dbdac495244d659aa1498b6`，与 [MAME 的 X68000 ROM 登记](https://github.com/mamedev/mame/blob/master/src/mame/sharp/x68k.cpp)一致；不是现代 Shinonome 替代字库。

文件来源记录见 [retrobios 的 cgrom.dat 条目](https://github.com/Abdess/retrobios/blob/main/bios/Sharp/X68000/cgrom.dat)。公开可访问不等于获得使用或再分发许可，目前未确认这份 CGROM 字库的相关权利。Sharp 针对 IPL 固件的历史授权不能推及 CGROM；归档工具的许可证也不覆盖所收录的 ROM。获取与后续使用前请自行核实权利。

[日本信息处理学会计算机博物馆](https://museum.ipsj.or.jp/computer/personal/0038.html)记录 X68000 于 **1987 年 3 月**推出，内置 ANK、JIS 第一及第二水准字符发生器 ROM，字符 ROM 容量为 768 KiB。这是机型日期，不是这份镜像对应物理芯片的已证实生产或转储日期。

## 本地导出

仅依赖 Python 3 标准库，离线运行。脚本只把 ROM 作为数据读取，不执行固件、不联网、不自动下载。从仓库根目录运行：

```sh
python3 scripts/sharp_x68000_to_bdf.py \
  --rom /path/to/cgrom.dat \
  --output /path/to/new-sharp-export
```

输出 `sharp-x68000-16x16.bdf` 与 `export-report.json`；报告记录源文件、输出 BDF、Unicode 映射及点阵数据的校验值和覆盖数量。输入必须通过大小及 SHA-256 校验，源路径与输出路径不接受符号链接；输出目录必须尚不存在。所有数据校验均在写入前完成，不提供强制跳过校验或覆盖选项。重跑请使用新目录；磁盘写入失败仍可能留下部分输出，应检查报错后另选新目录重试。完整结果不纳入公开仓库或网站；向指定接收者私下交付不代表获得 CGROM 或完整字体的公开再分发许可。

## 映射与覆盖范围

布局依据 [Puni 的 X68000 程序员资料](https://github.com/kg68k/puni/blob/main/programmers.txt)及独立逐槽核验：

- CGROM 地址基址为 `0xF00000`。16×16 字模位于文件偏移 `0`，每字 32 字节，逐行存储，每行两字节，高位为左侧像素。
- 两字节 JIS 分组为高字节 `0x21–0x28`、`0x30–0x4F`、`0x50–0x74`；低字节均为 `0x21–0x7E`，共 7,238 个物理槽位。设高字节为 row、低字节为 cell，row 小于 `0x30` 时槽号为 `(row-0x21)*94+cell-0x21`，否则为 `(row-0x30+8)*94+cell-0x21`。独立顺序遍历与该公式逐槽一致。
- Python 的 `euc_jp` 编码表可映射其中 6,879 个代码，但后增字符“凜”（JIS `0x7425`）与“熙”（`0x7426`）在此 ROM 中为空，必须排除，不借字、不补画。保留全角空格后导出 6,877 字；这些分组内没有未映射的非空槽位。
- 这是 JIS 字库，不是完整 GB2312 简体中文字库。固定繁体字样“視野無限廣，窗外有藍天。”全部有原始字形，无需替换或回退。
- **本工具不导出 ANK 或普通 ASCII。** ROM 另有位于文件偏移 `0x3A800`、每槽 16 字节的原生 8×16 ANK 区；目录展示的 216×34 原生像素双行样图含有从该独立区提取的安全 8×16 ANK 样例；它与仅含 JIS 字形的本 BDF 范围不同，不代表 BDF 包含 ANK。历史 JIS X0201 的相应槽位可能是日元符号“¥”而不是 ASCII 反斜线“\”，不能把该样例当作通用 ASCII 覆盖证明。

## BDF 度量约定

输出为 Unicode BDF 2.1，原生 16 像素字框：`SIZE 16 72 72`、`BBX 16 16 0 0`、`DWIDTH 16 0`、`SWIDTH 1000 0`、`FONT_ASCENT 16`、`FONT_DESCENT 0`。XLFD 为 14 字段，分辨率为 72 dpi（16 ppem），每行恰好两字节。

16/0 基线是保留完整字框的合成导出包装，并非已恢复的历史排版度量；不移动墨迹、不去掉空白边缘，也不声称恢复原机排版效果。

## 与现有字库的比较

已对全部 6,353 个 JIS 第一、第二水准汉字逐像素比较：

- 原生 16×16 与 X.Org `jiskan16` 及目录内 JF-Dot `jiskan16s` 对照，6,352 字不同，仅“亅”一致；去除外侧空白边缘后结论相同。
- 原生 24×24 的全部 6,353 个汉字与 `jiskan24` 完全一致，因此不作为新设计建立条目，**本工具不导出 24×24**。该结论针对上述汉字集合，不扩大为所有符号均已比较。

另对目录中 52 个 16×16 字框条目做过共享汉字样本比较，没有参考字体在全部已比对的共享字符上匹配；这只是样本检查，不是与 52 套字体的全库比较，也不证明独占来源或授权。
