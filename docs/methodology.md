# 研究方法与核验边界

## 1. 先追溯，再展示

记录作者／机构、项目或资料页、版本、文件格式、字号与提取方式。优先核对作者和官方资料，历史镜像则注明来源层级。能读取一个文件，只能证明该文件提供了什么，不能据此推导其最初设计方法或再分发许可。

## 2. 区分原生像素与普通轮廓取模

- BDF / PCF 等点阵文件：直接读取保存的像素，不平滑、不描粗、不任意缩放。
- TTF / TTC 内嵌点阵：选择对应的 EBDT/EBLC 或 bdat/bloc 等位图表及 strike；轮廓层和点阵层分开判断。
- 像素轮廓封装：仅在有原生网格设计依据时恢复像素格点。轮廓格式本身既不能证明“非点阵”，也不能证明“原生手工”。
- 普通矢量字体栅格化：不因为结果为黑白图片就视为新的原生点阵字体。

直接读取位图与证明原创手工设计，是两项不同的结论。

## 3. 尺寸不能只看图片

**ppem** 是所选像素字号；**字符框／单元** 是布局中为字符安排的尺寸；**墨迹边界** 是实际非空像素的包围范围。三者可能不同。bearing、advance、下伸部和行距也会影响样图尺寸。

例如“5×7 字面、6×8 字框”应按 8px 字高筛选，不能把字面高度当成完整字符框高度。预览放大 3 倍不产生新的原生字号。

## 4. 样文与缺字

普通字体分别使用简体“视野无限广，窗外有蓝天。”或繁体“視野無限廣，窗外有藍天。”，并配数字、拉丁字母和符号样文。OSD 仅展示来源实际可用的设备字符，不强行改成统一长句。

查找实际码位，不把简体字符冒充繁体字形。没有的字符保留透明位置并注明，不从另一字体补字。若整行没有任何字形，可省略整条空白行，但保留缺字记录。

“该点阵字号不含 ASCII”不等于整个字体文件没有西文。应分别检查 cmap、轮廓层和该 strike 的位图覆盖。

## 5. 重复与代表条目

先核对所比较文字、原生尺寸、像素、字宽和来源。完整 PNG 一致与仅中文样行一致，应分别描述。样文一致可以支持合并展示，但不能推断完整字库相同、互相复制或许可相同。

代表条目应尽量选择来源清楚、样文完整的版本；其他来源作为详情记录保留。只有少数字形的细微差别时，不仅凭文件名或版本号扩充目录。未经核验的近似项不自动合并。

## 6. 设备 OSD 的证据层级

文档网格重建不等于取得真实 ROM；ROM 字节解码不等于在实机上确认了缩放、前景／背景规则和最终画面；CRT 图像的扫描与显示比例也不等于字模本身的像素尺寸。每层结论按其依据记录。

## 7. 可复核的输出

目录同时维护 JSON 和浏览器可直接加载的 JS，两者内容一致。PNG 保留原始像素尺寸与校验值；测试检查条目唯一性、引用文件、尺寸、筛选和收藏／比较逻辑。公开包只包含固定预览及资料说明，不包含完整字库、ROM 或原始字形数组。

这些检查不替代完整字体覆盖检查、历史设计归属考证、许可审核或真实浏览器视觉验收。

## 8. 参考资料图与原生字样分开

官方网页试字截图、标准图样、历史外字图片标记为 reference。保留来源原图及必要裁切说明，不用截图宽高推测字框，不将浏览器抗锯齿截图称为 1× 原生点阵。未核定的宽、高和 cellWidth / cellHeight 为空值，官方标称尺寸单独记录。参考资料不参加普通样文完整性统计。

原生字样的目录 width / height 按排布字框记录，ppem、设计格数和实际墨迹另列证据。全角英数和普通 ASCII 分开，只有来源实际包含并绘制了普通 ASCII 时，才评价该行的完整性。无 ASCII 的独立中文字库保留说明，而非借字补行。
