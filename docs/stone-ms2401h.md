# 四通 MS-2401H：四套 32×32 汉字导出

这四套原生点阵来自 MS-2401H 的压缩字模区。每套有 **6,763 个 GB2312 汉字**；解码后的字符框都是 32×32，不放大、不描摹、不用其他字体补字。网站仅提供固定字样与提取工具，完整 ROM 和导出字库不随仓库或网站分发。

## 本地导出

依赖：Python 3.9+ 标准库；导出和常规测试均不需要 Pillow。以下命令从仓库根目录运行，`local-research/stone-roms` 是自行准备的输入目录，输出目录必须尚不存在：

```sh
python3 scripts/stone_ms2401h_to_bdf.py \
  --rom-dir local-research/stone-roms \
  --output local-research/stone-bdf
```

输出四个 `stone-ms2401h-style-{1,2,3,4}-32x32.bdf` 和一个 `export-report.json`，报告包含输入、输出与解码位图的校验值。脚本在全部数据校验通过后才创建输出目录，不覆盖已有文件或文件夹；重跑请选用新的输出目录。发生磁盘写入失败时可能留下部分输出，请检查报错并另选新目录重试。完整结果留在本地，不要将其提交或上传到网站。

## 风格编号与覆盖范围

| 精确标识 | 视觉分类（暂定） | 导出范围 |
|---|---|---|
| style 1 | 楷体 | 6,763 个汉字 |
| style 2 | 黑体 | 6,763 个汉字 |
| style 3 | 仿宋 | 6,763 个汉字 |
| style 4 | 宋体 | 6,763 个汉字 |

视觉分类与机器字处理菜单字样一致，但尚未完整追踪菜单到 BIOS 字体编号的调用路径，因此文件名以编号为准，不把推断当作确定的字体名称。

- 汉字区按 B0A1–F7FE 的 6,768 个槽位解码。D7FA–D7FE 是五个未分配空槽，排除后通过 Python 的 GB2312 编码表映射到 Unicode；不是 GBK 扩展或繁简转换。
- 四套有效汉字槽位均非空。默认仅导出汉字；加 `--include-symbols` 可补入共享 style 0 的 682 个 GB2312 符号（含全角英数及标点），每套共 7,445 字。全角 `ＡＢＣ１２３` 保持原码位，不替代普通 ASCII。扩展区较窄西文的输入映射及排版宽度尚未确认，暂不导出。
- 每个字模保留全部 32×32 像素及空白边缘。四条 8×32 纵向字节带只重排为逐行字节，不插值、不裁切、不移动墨迹。
- BIOS 先清零 128 字节字框，因此压缩流省略的尾部仍为零。字节对齐可能解出超过 128 字节，只有溢出部分全零才接受；非零溢出会报错。

## BDF 度量约定

输出为 Unicode BDF 2.1：`BBX 32 32 0 0`、`DWIDTH 32 0`、`FONT_ASCENT 32`、`FONT_DESCENT 0`。32/0 基线是为了保存字框而采用的导出包装，不是已经恢复的历史排版基线；`SWIDTH 1000 0` 与 72 dpi、32点的头部同为常规包装（32 ppem）；XLFD 为14字段，`RESOLUTION_X/Y` 同为72。每行恰好四字节，高位对应左侧像素。此导出不声称恢复了原机排版效果。

## 提取依据与验证

BIOS 描述表从文件偏移 `0x59A6` 开始，每项七字节，字节排列查找表从 `0x59C9` 开始，每套 256 字节。解压依据静态分析的 BIOS `0x57AC–0x580F`、位读取与边界检查 `0x5888` / `0x5898`；数据存储跨 CA1、CA2、CA3 地址段。脚本同时核对描述表位置、6,768 条记录连续性、压缩范围、空槽位置和完整解码结果 SHA-256。

公开测试无需 ROM：

```sh
python3 tests/stone-export.test.py
```

测试覆盖新秩与重复秩、截断尾位、零填充、非零溢出拒绝、字节带重排、GB2312 映射、BDF 度量、缺失／错误输入、已有输出与符号链接拒绝、XLFD 14字段；若系统安装了 FreeType，还会验证字体原生 strike 为32×32 ppem（否则仅跳过这一可选测试）。

本次另用已核验 ROM 完成实际导出：四套各 6,763 字与先前独立研究 BDF 的 Unicode 码位及全部 32×32 位图逐一相同；固定样文“视野无限广窗外有蓝天”四张 320×32 样图的墨迹掩模也逐像素一致。这项验证不表示与其他来源字库做过全库比较，也不构成再分发许可。
