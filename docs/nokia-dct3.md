# Nokia DCT3 1999 中文点阵

这套字形直接来自 Nokia 6150（NSM-1）5.17 版 E 语言包的已存储单色位图。固件头标记日期为 **1999-07-01**，不是字形首次设计日期。汉字为 **11×12**，简繁兼有。

## 来源与覆盖

- [固件存档页面](https://archive.org/details/Nokia_DCT3_firmwares)。本地核验输入为 `nsm-1_v5.17.exe` 包中的 `nsm1ny_5.17e`。该包可作为 ZIP 读取；不需要执行安装程序或刷写手机。
- [DCT3 FONT 格式研究](https://pjmor.com/extract-nokia-dct3-fonts/)。本站脚本独立实现静态解析，只接受已核验输入的大小和 SHA-256。
- 输入大小：656080 字节；SHA-256：`6fc1ac3669091c615d22ebccb39ee0e056239fd1a0ab99a44053a52ad26cc444`。
- `large-bold` 是固件中的字体记录名称，不另行推断中文字体的商业名称或设计者。
- 该记录有 9385 个原始 Unicode 码位，其中 9004 个 U+4E00–U+9FFF 汉字，覆盖 GB2312 全部 6763 个汉字，另有 2241 个汉字。包含繁体，但没有据此声称覆盖全部 Big5、GBK 或 Unicode 汉字。
- 9004 个汉字均为非空 11×12 位图。西文保留原始不等宽字模；其常见字框高13，不能把整条字体记录说成全都11×12。

6150 的5.17与5.20、6110的5.47D、8810的5.00D四份1999固件中，9004个汉字的码位、尺寸和逐像素结果完全一致，因此只收录一条。另已核验6110的5.40D，固件头日期为 **1999-05-25**，其中9004个汉字也与主来源逐像素相同。这只能证明该套字形已在这一日期的固件中出现，不证明首次设计或首次发行时间。6110的5.47E只有695个汉字，是同一套字形的子集。型号或语言包字母不能单独保证覆盖范围。

## 离线导出

自行取得并确认有权处理上述文件，放入被忽略的 `local-research/`。导出只用Python 3标准库，无网络请求、外部程序、固件执行或系统字体依赖。安全文件操作要求支持 `O_NOFOLLOW` 和目录文件描述符的POSIX环境（如Linux）；缺少该能力会明确拒绝，不降级为跟随符号链接的写入。

```sh
python scripts/nokia_dct3_to_bdf.py \
  --font local-research/nsm1ny_5.17e \
  --output local-research/nokia-dct3-1999.bdf
```

默认导出 `large-bold` 的9385个码位，同时在同一目录生成同名JSON核验报告。仅需9004个汉字时加 `--cjk-only`，也可用 `--report local-research/reports/nokia.json` 另定报告位置。

BDF和JSON都只能新建在当前工作目录的 `local-research/` 内，不能覆盖输入或任何已有文件；路径不得含符号链接或 `..`。输入只读打开，拒绝符号链接、目录和FIFO等非普通文件。全部解析、覆盖和像素校验通过后才创建输出；第二个文件写入失败会尝试移除本次已创建的文件。新输出权限为仅当前用户可读写。没有 `--force`、跳过哈希或接受未知版本的开关。脚本不会下载、解包或执行EXE，也不接受仅文件名相同的未知版本。

## 编码和像素

1. 验证完整输入的大小和SHA-256。
2. 去除80个Wintesla块的9字节传输头，检查块长度与地址连续性，得到655360字节PPM。
3. 从唯一的 `FONTfconv` 位置进入字体数据。检查记录、索引、矩阵和字符组边界、重复码位及Unicode代理区间。原字符组直接记录Unicode起止码位，不使用GB码位猜测或OCR。
4. 字符共享按宽度分组的位图矩阵；每字节存8个纵向像素，最低位在上。这里是位打包，不是矢量轮廓取模，也不需要字形压缩算法。
5. 保留每字宽度、高度和记录低5位度量字段的值。沿用已核验BDF的映射，将该字段解释为基线值：`BBX` 的纵向偏移为“字段值减字框高度”，横向偏移为0，`DWIDTH` 为矩阵宽度。这是导出度量的解释，不是真机排版的独立实测；不推断真机可能另加的字符间距。字符框留白不裁切，不补缺字。
6. 完整记录的BDF包围框为12×15，ascent/descent为11/4；它容纳13高西文和不同纵向度量，不能称作全库11×12或真机15点行高。仅汉字导出为11×12，ascent/descent为11/1。两种导出均保留同一批汉字的原始像素和单字偏移，不缩放。
7. 检查9385个总码位、9004个非空汉字、GB2312全部6763个汉字，并复核“Unicode＋原度量＋全部逐行像素”的独立SHA-256。检查使用显式异常，`python -O` 不会关闭它们。

公开测试只用自造记录和像素，覆盖纵向位打包、跨字节字符组、解析边界、重复码位、11×12汉字与13高西文的BDF度量，以及文件覆盖、路径逃逸、符号链接替换和输出失败回滚。普通Python与 `python -O` 均运行同一套检查。可选的系统FreeType只用于测试实际BDF位图层、bearing、advance和像素，不是导出依赖。

私有输入验收另外将9385码位逐项对照此前核验的BDF及独立字模记录，核对Unicode、尺寸、纵向偏移、advance和全部像素；9004汉字子集也逐项核对。FreeType在完整导出的15ppem和仅汉字导出的12ppem位图层分别读取全部9385及9004个字形，度量与像素均一致。这里的ppem是导出包围框，不证明真机字号或行距。没有逐字人工校对，也没有真机显示验证。

与13份已有11/12点原字库按同一Unicode逐字比较，包含HZK12、HZK11US、Firefly、MingLiU、文泉驿、Mac Hei、Dotum、文曲星、Casio和Palm CJKOS。即使仅移除空白外边界再比对墨迹，也不是相同字库。简单字偶合不等于同一套来源。
